# 文档体系搭建指南 — 让新会话AI自动进入状态

## 问题
每次开新会话、压缩上下文后，AI对项目一无所知，需要重新解释半天。解决方法是建一套"自文档化"体系——AI启动时自动读取项目设定，顺着指引找到所需文档，一分钟进入状态。

## 核心思路
不是建一个巨型文档让AI记住一切，而是**建一条阅读链**——每份文档只负责指引下一份，AI顺着读就行。

## 具体做法

### 第一步：写 CLAUDE.md（入口文件，自动加载）
Claude Code 启动时自动读取项目根目录的 `CLAUDE.md`。在这个文件里放：
- 项目是什么（一句话）
- AI的角色定位（一句话）
- **关键**：在 "Active Documents" 章节列出新会话必须读的文档，第一条指向启动指南

```markdown
## Active Documents

新会话启动时，先读启动指南建立认知，再讨论任务：

1. `docs/ai-startup-guide.md` — **新会话必读**
2. `docs/handoff.md` — 交接文档
3. `docs/plans/execution-log.md` — 执行记录
```

### 第二步：写 ai-startup-guide.md（启动指南）
这是新会话AI的第一份读物。分三步：
- **第一步**：列几个文件让AI建立项目认知（项目摘要、模块架构、AI人设、用户指南）
- **第二步**：让AI读交接文档和执行记录（了解当前进度）
- **第三步**：让AI读具体模块的文档（进入工作）

每步都是一个简单的文件列表，不需要长篇大论。

### 第三步：写 handoff.md（交接文档）
每次会话结束前更新，记录：
- 各模块当前状态（✅已实现 / 🔨进行中 / ❌待开发）
- 关键技术决策
- 核心文件清单（新会话AI需要知道哪些文件最重要）
- 快速启动命令

保持在**70行以内**——这是"压缩上下文"，不要写成流水账。

### 第四步：写 execution-log.md（执行记录）
每次有实质产出后追加一行：
```
[日期 时间] [Agent名称] 完成了什么 / 产出了什么文件
```
时间必须用命令获取真实时间，不能编造。这个是完整历史的流水账，和交接文档互补——交接文档是"最新的快照"，执行记录是"完整的历史"。

### 第五步：建 update-handoff 技能（自动化）
在 `.claude/skills/update-handoff/SKILL.md` 创建一个技能，描述每次压缩上下文前自动更新交接文档和执行记录的流程。建好后，说"更新交接文档"就能自动执行。

### 第六步：写 module-architecture.md（模块全景图）
如果项目有多模块，写一个全景图展示模块之间的依赖关系和数据流方向。新会话AI一眼就能看清整体结构。

### 补充：写 ai-persona.md（AI人设）
描述AI在这个项目中应该扮演什么角色、用什么工作风格、有哪些优势和弱点。放在 CLAUDE.md 的概览部分引用，新会话启动时作为必读文档之一。

## 阅读链的完整流向

```
CLAUDE.md（自动加载）
  └─→ ai-startup-guide.md（启动指南）
        ├─→ project-brief.md（项目摘要）
        ├─→ module-architecture.md（模块全景图）
        ├─→ ai-persona.md（AI人设）
        ├─→ handoff.md（交接文档）
        └─→ execution-log.md（执行记录）
              └─→ 具体模块的契约+设计文档
```

## 维护节奏
- **每次压缩前**：运行更新交接文档
- **每次有了实质产出后**：更新执行记录
- **模块状态变化时**：更新交接文档的进度表
- **技术决策变化时**：更新交接文档和CLAUDE.md
