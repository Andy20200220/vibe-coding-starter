帮助非技术用户把粗糙的想法整理成清晰的产品定义和行为契约。

要求：
- 读取行为契约技能：`.claude/skills/behavior-contract/SKILL.md`。
- 用户不懂代码。所有沟通必须使用大白话，不用技术术语。
- 不得跳到代码、技术设计或实现。本命令只产出文档。

## 第一阶段 — 理解想法

向用户提问，弄清楚：
- 这个工具解决什么问题？谁在用？
- 在哪里运行？（本地应用、网页、手机端等）
- 单人使用还是多人使用？
- 能想到的所有功能是什么？（鼓励列出完整清单，哪怕很粗略）
- 第一个版本最重要的 3 个功能是什么？

不得假设答案。明确提问，等待确认。

## 第二阶段 — 产品定义

根据已确认的回答，产出一份简短的产品定义，包含：
- 一句话产品用途
- 目标用户
- 运行平台
- 完整功能列表（用户提到的所有功能，编号列出）
- MVP 范围（第一个版本的 3 个功能，明确标注）
- 第一个版本不做的功能（其余功能，明确列出）

请用户确认或修改此产品定义，然后再继续。

## 第三阶段 — MVP 功能的行为契约

对每个 MVP 功能，产出行为契约：
- 列出每个用户操作（如"用户点击 X 按钮"）
- 对每个操作，说明预期的系统响应
- 对每个操作，说明出错时发生什么（输入为空、数据无效、重复等）
- 说明用户如何验证这个功能正常（具体的操作步骤和检查点）

使用大白话。不用技术术语。不引用代码。

请用户逐条确认每个行为契约条目。用户不确定的条目标记为"待定 — 需要决策"。
